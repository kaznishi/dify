> useSWRとはなんですか？

✦ useSWR は、データ取得のための React Hooks ライブラリです。名前は "Stale-While-Revalidate" というキャッシュ戦略に由来しています。

  これは、UIの表示を高速化するための非常に効果的な戦略です。

  Stale-While-Revalidate (SWR) の中心的な考え方

  SWRは、以下のステップで動作します。


   1. Stale (古い) データをまず表示: まずキャッシュにあるデータ（Staleデータ）をすぐに画面に表示します。これにより、ユーザーはローディングを待つことなく、すぐに
      何かしらの情報を見ることができます。
   2. While (その裏側で) Revalidate (再検証): キャッシュを表示している間に、裏側で最新のデータを取得するリクエスト（Revalidate）を送信します。
   3. 最新データで更新: 最新のデータの取得が完了したら、画面を新しいデータに更新します。


  この戦略により、「表示が速い」という利点と「データが常に最新に保たれる」という利点の両方を享受できます。

  useSWR の使い方

  基本的な構文は以下のようになります。


   1 const { data, error, isLoading } = useSWR(key, fetcher, options)



   - key: データの一意な識別子です。通常はAPIのエンドポイントURLや、リクエストに必要なパラメータのオブジェクトが使われます。
   - fetcher: 実際にデータを取得する非同期関数です。key を引数として受け取ります。
   - data: fetcher が返したデータです。取得中は undefined になります。
   - error: fetcher がエラーを投げた場合に、そのエラーオブジェクトが入ります。
   - isLoading: 初回のリクエスト中で、まだキャッシュされたデータもない状態のときに true になります。

  WorkflowCostChart での使われ方

  先ほどのコードでは、以下のように使われています。



   1 const { data: response } = useSWR({ url: `/apps/${id}/workflow/statistics/token-costs`, params: period.query }, getAppTokenCosts)



   - key: { url: ..., params: ... } というオブジェクトです。useSWR はこのオブジェクトを getAppTokenCosts 関数に渡します。
   - fetcher: getAppTokenCosts 関数です。この関数が実際にAPIを叩いてデータを取得します。
   - data: response: getAppTokenCosts が成功すると、その戻り値が response という名前の変数に格納されます。

  useSWR の主な利点


   - パフォーマンス: キャッシュを即座に返すため、ユーザー体験が向上します。
   - 自動再検証:
       - ウィンドウにフォーカスが戻った時
       - ブラウザが再接続した時
       - 設定した間隔 (interval)
      に自動でデータを再取得し、常に画面を最新の状態に保とうとします。
   - 状態管理の簡素化: ローディング状態 (isLoading) やエラー状態 (error) をフックが管理してくれるため、自分で状態を管理するコードを書く必要が減ります。

   - URL: /apps/<uuid:app_id>/workflow/statistics/token-costs-by-model
   - メソッド: GET
   - ファイル: api/controllers/console/app/workflow_statistic.py に新しいリソースクラスを追加します。
   - クラス名: WorkflowTokenCostByModelStatistic

  1.2. 処理内容

  このエンドポイントは、指定されたアプリケーションと期間において、成功したLLMノードの実行ログを集計します。


   1. データベースクエリ:
       * 対象テーブル: workflow_node_executions
       * 集計ロジック:
           * app_id と期間 (start, end) でレコードをフィルタリングします。
           * node_type が 'llm' (LLMノード) で、status が 'succeeded' のレコードのみを対象とします。
           * execution_metadata JSONカラムから model_name を抽出します。
           * model_name でグループ化し、各モデルの total_tokens を合計します。
           * 結果をトークン使用量の降順でソートします。

      SQLクエリ (PostgreSQL) の例:


    1     SELECT
    2         jsonb_extract_path_text(execution_metadata, 'model_name') AS model_name,
    3         SUM(CAST(jsonb_extract_path_text(execution_metadata, 'total_tokens') AS integer)) AS total_tokens
    4     FROM
    5         workflow_node_executions
    6     WHERE
    7         app_id = :app_id
    8         AND created_at >= :start
    9         AND created_at < :end
   10         AND node_type = 'llm'
   11         AND status = 'succeeded'
   12     GROUP BY
   13         model_name
   14     ORDER BY
   15         total_tokens DESC;



   2. レスポンス形式:
       * 以下の形式のJSONを返します。


   1     {
   2       "data": [
   3         { "model_name": "gpt-4", "total_tokens": 10520 },
   4         { "model_name": "claude-3-opus", "total_tokens": 8765 },
   5         ...
   6       ]
   7     }

  でURLとクラスを紐付けます。
